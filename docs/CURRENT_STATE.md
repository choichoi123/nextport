## Git 변경 분할과 원격 반영

- 2026-11-11 사용자가 앞서 제안한 분할 commit·push를 승인했습니다. 기존 `master`와 `origin`을 유지하고 실행·Notion 안정화, 새 화면, 표지 자료, 규칙·문서의 네 단위로 구성했습니다. 시작 전에 원격을 다시 조회해 기준 `e1583a0`과 일치함을 확인했습니다. 전체 초기화·강제 push·다른 저장소 변경은 하지 않습니다.

| 1 | `fix: 로컬 실행 및 Notion 조회 안정화` (`ca5bae0`) | Node·패키지·실행 호환성과 안전한 Notion 조회. 기존 목록의 `{ results }` 계약을 유지하는 중간판을 Git 인덱스에만 구성. 해당 사본에서 테스트 22개 통과·빌드 성공·정적 페이지 6개 생성 |

- 빌드는 Git에 들어갈 내용을 각각 별도 Temp 사본으로 추출해 수행했습니다. 원본과 실행 중인 3001·3005의 `.next`, 로컬 Notion 환경변수·읽기 권한과 브라우저 탭을 보존했습니다. 최종 프로젝트 목록 작업 파일을 중간판으로 덮지 않았으며, 보관 홈의 줄 끝 공백만 정리했습니다. 기존 Browserslist 안내 외 빌드 오류는 없었습니다.
- 한글 커밋 메시지는 저장소 밖 UTF-8 파일로 작성하고 Git에 저장된 원문이 해당 메시지와 일치하는지 검사합니다. 변경 텍스트의 UTF-8 디코딩·대체 문자·BOM과 `git diff --cached --check`를 확인하며 실제 `.env.local`·미리보기 키·임시 검증 파일은 커밋 대상에서 제외합니다.
- 원격 반영 식별자는 [master 커밋 이력](https://github.com/choichoi123/nextport/commits/master/)을 기준으로 합니다. push 이후 Git 원격 ref와 로컬 HEAD의 일치를 확인하며, 이번 작업에서 공개 사이트의 새 배포 성공이나 배포 환경의 Notion 연결 전환을 확인한 것으로 해석하지 않습니다. Notion 본문은 DB에 저장된 별도 상태이며 코드 커밋에 포함되지 않습니다.

1. **계정 복구와 운영 연결:** 소유 확인 자료 확보 또는 메일함 복구 불가 시 대체 본인확인 절차에 대한 추가 문의가 남아 있습니다. 추가 제출·회신은 사용자 요청 범위에서 진행합니다. 개인 복제본은 확보했으며, 사이트 조회 대상을 전환하려면 새 DB의 읽기 연결·데이터 소스·상세 공개 범위와 배포 환경을 확인해야 합니다. 현재 배포는 전환하지 않았습니다.
