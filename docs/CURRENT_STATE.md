- 실제 인증값·쿠키·전체 응답·서명 URL을 새 로그나 파일에 출력·저장하지 않았습니다. 원격 파일·Git 이력·토큰·권한·환경변수·배포는 변경하지 않았고 새 commit·push도 수행하지 않았습니다. 이번 로컬 변경은 위 제외 규칙과 이 점검 기록이며 기존 미커밋 문서는 보존했습니다. 연동 식별자의 공개 문서 분리는 이후 아래 작업에서 진행했으며, 과거 Git 이력은 유지합니다.

## 실제 연결 ID의 비공개 관리 분리

- 2026-11-12 사용자 요청으로 공개용 Notion 문서·Vercel 전환 안내·이 상태 문서의 실제 DB·데이터 소스 ID를 역할별 예시 표기로 교체했습니다. 관리용 상위 페이지·DB URL과 ID 앞부분 예시도 함께 정리했고, 방문자용 공개 프로젝트 상세 ID·링크와 대표작 선택 코드는 보존했습니다. 예시를 실제 환경변수 값으로 붙여 넣지 않도록 안내하며, 기본 데이터 소스 자동 탐색 방식은 유지합니다.
- 실제 관리 식별자와 URL은 저장소 밖 **`%LOCALAPPDATA%/nextport/private/NOTION_CONNECTIONS.md`**로 분리했습니다. 현재 관리본·회사 원본·이전 개인 자료를 구분한 7개 관리 대상과 기존 운영 설정의 의미를 보관하며 API 토큰·쿠키·비밀번호는 넣지 않았습니다. 새 비공개 디렉터리의 접근 권한 상속을 차단하고 현재 Windows 사용자·SYSTEM·관리자만 허용했습니다.
- 공개 자료에는 [비공개 관리 자료 안내](NOTION.md#공개-문서와-비공개-관리-자료)를 두고, 다른 PC에는 파일이 자동으로 존재하지 않는다는 점과 허용된 Notion·Vercel 관리 화면에서 확인하는 경로를 명시했습니다. [AGENTS](../AGENTS.md)의 공개 문서 기준에도 실제 관리 ID·URL과 공개 프로젝트 상세 링크를 구분하도록 반영했습니다.
- 비공개 분리 직후에는 로컬 문서만 정리했습니다. 코드·환경 파일·Notion 데이터와 연동·Vercel 설정·배포를 바꾸지 않았고 기존 미커밋 변경도 보존했습니다. 이 시점에는 원격 저장소에 이전 값이 남아 있었으며 commit·push·이력 재작성을 수행하지 않았습니다. 이후 문서와 제외 규칙의 원격 반영 범위는 아래에 기록합니다.
- 관리 식별자 7종의 전체값·UUID·URL·부분 접두어를 작업 파일 72개에서 검사해 잔존 없음을 확인했습니다. 실제 값의 비공개 복사본과 저장소 밖 위치·접근 권한, 공개 프로젝트 ID와 제작 기록 보존, 코드·자산·환경 파일 등 62개 보호 파일의 바이트 불변과 Git HEAD·커밋 수·인덱스 불변도 대조했습니다. 공개 `/`·`/projects`의 HTTP 200·`source: notion`·프로젝트 7개, 대표 순서와 파주 월 표시를 확인했습니다. 브라우저를 조작하거나 탭을 닫지 않았으며 제품 테스트·빌드는 실행하지 않았습니다.
- 공개 문서 5개와 비공개 자료의 UTF-8·BOM·대체 문자·줄 끝 공백, 로컬 링크 70개·앵커 11개와 `git diff --check`를 확인했습니다. 자리표시자를 넣은 활성 가짜 URL은 없습니다.

## 공개 문서와 Git 제외 규칙의 커밋 범위

- 2026-11-12 사용자가 실제 관리 ID의 잔존 여부를 재검사하고 문서 정리와 `.gitignore` 보완을 commit·push하도록 승인했습니다. 대상은 `.gitignore`, `AGENTS.md`, `README.md`, `docs/NOTION.md`, 이 상태 문서와 `docs/VERCEL_NOTION_MIGRATION.md`의 6개 파일입니다. 앞선 운영 DB 전환·상세 공개·비공개 분리 기록과 배포 안내도 함께 포함합니다.
- 사전 검사에서 작업 파일 72개에 실제 관리 식별자 7종의 전체값·UUID·관리 URL·문서의 부분 접두어와 실제 인증 토큰 형태가 남아 있지 않음을 확인했습니다. 공개 프로젝트 상세 ID·링크는 유지합니다. 비공개 관리 파일은 저장소 밖에 두고 커밋 대상에서 제외하며, 코드·실제 환경 파일·Notion 연결·권한·Vercel 설정을 수정하지 않습니다.
- 수정 파일 6개의 UTF-8·BOM·대체 문자·줄 끝 공백, 로컬 링크 70개·앵커 11개, 환경 파일 제외 7개 사례를 확인했습니다. 커밋 직전에는 인덱스의 실제 포함 파일·관리 ID·비밀값·문자 인코딩을 다시 확인하고 `git diff --cached --check`를 수행합니다. 제품 코드 변경이 없어 로컬 제품 테스트·빌드는 반복하지 않습니다.
- 기존 커밋을 부모로 하는 일반 커밋으로 추가하며 amend·강제 push·과거 이력 재작성을 하지 않습니다. 한글 메시지는 저장소 밖 UTF-8 파일로 전달하고 Git에 저장된 메시지와 파일 바이트를 대조합니다. 커밋 식별자와 원격 반영 여부는 [master 커밋 이력](https://github.com/choichoi123/nextport/commits/master/) 및 실제 원격 ref로 확인합니다. Git push에 따른 자동 배포 여부와 새 배포 성공은 별도의 확인 대상입니다.
