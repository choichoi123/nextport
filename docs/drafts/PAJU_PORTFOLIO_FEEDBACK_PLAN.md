# 파주 포트폴리오 추가 피드백 반영 계획서

기준일: **2026-11-11**. 현재 개인 Notion 항목과 파주 담당 AI의 최신 전달 자료를 비교한 후속 계획입니다. 기존 [1차 계획](PAJU_PORTFOLIO_WRITING_PLAN.md)과 [보완 초안](PAJU_PORTFOLIO_REVISED_DRAFT.md)은 당시 검토 기록으로 보존합니다.

**편집자용 로컬 참고 경로:** `Paju_voucher/...`는 nextport와 같은 상위 폴더의 별도 저장소 기준 경로입니다. 이 저장소에 포함되지 않는 문서·이미지는 활성 링크 대신 경로로 표기합니다.

이 문서는 반영 전 계획 기록입니다. 이후 사용자 승인으로 수행한 결과는 [현재 상태의 실제 반영 기록](../CURRENT_STATE.md#파주-추가-피드백-실제-반영)에서 확인합니다.

**기존 소개를 유지하면서 정적 웹 산출물 구조, iOS 12 모달 대응 사례, 탑승정보 화면을 보강합니다.** 이번 사용자 요청에서 실제 반영하는 것은 선택한 구성 표지의 교체이며, 아래 본문 보완은 계획 단계입니다.

## 3. 구간별 수정 계획과 공개용 문구

### 03절 — 정적 웹 산출물 구조를 한 번만 설명

현재 구조 문장의 첫 부분을 다음 문장으로 통합하고, 이어지는 지도 SDK 연결·백엔드 책임·본인 담당 경계는 유지합니다. 비슷한 문장을 앞뒤에 중복 삽입하지 않습니다.

> React 정적 웹 산출물을 이용자 앱의 WebView와 관리자 브라우저에서 로드하고, 기존 회원·접수·관제 API와 연결하는 구조입니다.

정적 웹 프론트엔드의 제공 형태를 설명하는 문장입니다. 네이티브 앱·웹 서버·호스팅·배포 인프라까지 본인이 개발했다거나 특정 초기 빌드가 운영에 배포됐다는 뜻으로 사용하지 않습니다. 별도 구성도 없이 한 문장으로 보강하는 안을 우선합니다.

### 04절 지도 사례 — 경로 확인 다음에 탑승정보 입력 추가

현재 ‘접수 전 경로 미리보기’ 이미지와 캡션 **다음**, 로그인·센터 회원 연동 사례 **앞**에 다음 묶음을 넣습니다. 기존 사진·캡션을 이동하거나 교체하지 않습니다.

**소제목 형식:** 굵은 문단 `탑승정보 입력`. 기술 사례와 같은 제목 수준으로 만들지 않습니다.

**설명:**

> 이용목적·휠체어·동승자·비고를 입력하는 탑승정보 화면을 구성해, 주소와 위치 확인부터 이용조건 입력까지 접수 흐름을 연결했습니다.

**사진:** `Paju_voucher/docs/portfolio-20261111/images/real-captures/02-trip-details.png`, 1080×2316의 기존 편집본 그대로 사용 예정.

**네이티브 이미지 캡션:**

> 이용목적·휠체어·동승자·비고를 입력하는 초기 개발 단계의 탑승정보 화면입니다.

실제 파일을 열어 이용목적·휠체어·동승자·비고, 접수하기·취소 버튼을 확인했습니다. 출발·도착 주소 입력란이나 접수 완료 화면으로 설명하지 않습니다. 2026년 3월 개발·테스트 화면이라는 기존 공통 설명을 유지하며 이 사진을 5월 iOS 수정 증거에 연결하지 않습니다. 이 계획 작성 중 이미지를 재편집하거나 업로드하지 않았습니다.

### 04절 회원 상태 사례 다음 — iOS 12 사례 추가

현재 회원 연동 사례의 마지막 문단 다음, `05. 결과와 검증` 앞에 제목 수준 3으로 추가합니다.

**제목: 구형 iOS의 주소·지도 모달 레이아웃 보완**

> 초기 개발 중 iOS 12에서 주소·지도 모달의 비율이 어긋나는 문제에 대응했습니다. 기존 지도 선택 흐름을 유지하면서 주소 목록과 지도 모달의 렌더링 구조, 위치·높이 스타일을 보완했습니다.
>
> 선택 항목 상태를 두고 지도 모달을 주소 목록 밖에 표시하도록 변경했습니다. 모달의 네 방향 위치·너비·높이와 내부 레이아웃·overflow를 명시하고 WebKit 높이·스크롤 관련 스타일을 조정했습니다.
>
> 2026년 5월 28일 코드 변경 기록에서 대응 내용을 확인할 수 있습니다. 별도 실기기 재현·수정 후 QA 결과는 확보하지 못했으므로 모든 구형 기기의 호환성을 검증한 것으로 설명하지 않습니다.

근거는 `2336a37`의 `src/components/AddressPopup.jsx`와 `src/css/layout.css`입니다. 사용자 확정 종료일 안의 초기 개발 사례이므로 하반기 유지보수와 구분합니다. 내부 파일 경로·커밋 표는 공개 본문에 복사하지 않습니다. 이 사례의 실제 수정 전후 기기 사진은 미제공이므로 억지로 기존 사진을 재사용하지 않습니다.

### 05·06절 — 추가 사례와 검증 범위의 일관성

- 05절의 기존 초기 구현 확인 문단에 iOS 모달 대응을 코드 변경 기록으로 확인했다는 사실을 짧게 연결합니다. 실기기 QA 미확인은 04절에 적은 범위와 동일하게 유지하고, 초기 빌드 운영 배포·정량 성과를 추가하지 않습니다.
- 06절의 3월 개발·테스트 사진 설명·전화번호 가림·운영 동작 검증 한계는 그대로 유지합니다. 준비된 원본 8개를 모두 게시한 것처럼 ‘이미지 8개’로 바꾸지 않습니다.
- 01·02절과 기존 표 2개는 새 사례를 위해 다시 쓰지 않습니다. 기존 제목·소개·기술 태그·월 단위 카드 표시·대표 순서에도 영향이 없습니다.

## 5. 향후 본문 반영 순서와 완료 기준

1. 같은 Notion 페이지를 다시 읽어 본 계획 이후 사용자 편집이 있는지 확인합니다. 전체 참고 원고로 본문을 덮지 않고 해당 구간만 편집합니다.
2. 03절 구조 문장을 통합하고, 04절의 경로 이미지 다음에 설명·02 이미지·캡션을 추가합니다.
3. 04절의 세 번째 사례를 추가하고, 05절 검증 설명을 새 사례와 맞춥니다.
4. 저장 후 본문 6개 절·기술 사례 제목 3개·표 2개·본문 이미지 6개와 배치·문구를 대조합니다. 기술 사례 제목과 사진의 굵은 소제목을 구분합니다.
