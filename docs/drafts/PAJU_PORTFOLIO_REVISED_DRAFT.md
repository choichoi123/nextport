## 2. 공개 본문

### 01. 프로젝트 개요

**파주 교통약자 이동지원 이용자의 모바일 이용 흐름과 관리자 회원 업무를 구현한 프론트엔드 프로젝트입니다.** 이용자는 앱 안의 웹 화면에서 회원가입, 주소와 탑승 위치 선택, 이동 접수, 이용내역 확인을 진행하고, 관리자는 웹 화면에서 회원 검색과 센터 회원 연동·승인 업무를 처리합니다.

| 항목 | 내용 |
| --- | --- |
| 참여 기간 | 2026.02~2026.05 |
| 개발 인원 | 백엔드 1명 · 프론트엔드 1명 |
| 내 역할 | 이용자·관리자 프론트엔드 전체, 백엔드 API 연동 |
| 사용 기술 | React · JavaScript · Redux Toolkit · React Router · Axios · Kakao Maps |

백엔드 개발자 1명과 협업하며 React 화면 구현, 화면 이동과 회원 상태 관리, 지도·위치 선택, 업무 API의 요청·응답 표시를 담당했습니다.

이미지 참고 — 초기 접수 경로, 자주가는곳 주소 검색, 본인인증 입력 화면을 배치한 대표 이미지: `Paju_voucher/docs/portfolio-20261111/images/real-overview.png`

*초기 개발 단계의 접수·주소 선택·가입 화면을 보여주는 실제 캡처 기반 자료입니다. 전화번호는 가렸습니다.*

### 02. 해결할 문제

이동 접수에는 출발지와 목적지뿐 아니라 실제 탑승 위치, 이용목적, 휠체어·동승 정보 등이 필요했습니다. 작은 화면에서 주소를 찾고 지도에서 위치를 확인한 뒤 탑승 조건을 입력할 수 있도록 연결해야 했습니다. 주소 검색 결과, 지도 좌표, 서버에 전달하는 선택값도 일관되게 다뤄야 했습니다.

회원 상태에도 별도의 업무 구분이 있었습니다. 웹 계정으로 로그인했더라도 센터 회원과 연결되어 있는지를 확인해야 접수 서비스를 이용할 수 있었습니다. 이용자에게 현재 상태를 안내하는 화면과, 관리자가 웹 회원을 찾아 센터의 관제 회원과 연결하고 승인 상태를 관리하는 화면을 함께 구성했습니다.

### 03. 내 역할과 시스템 구성

제가 이용자 모바일 WebView와 관리자 웹의 프론트엔드 전체를 담당했습니다.

| 담당 영역 | 구현 범위 |
| --- | --- |
| 이용자 화면 | 가입·로그인·계정 찾기, 회원정보, 이동 접수, 이용내역, 자주가는곳 |
| 지도와 위치 선택 | 주소 검색, 지도에서 위치 선택, 접수 전 예상 경로·거리·시간 표시 |
| 관리자 화면 | 로그인, 웹 회원 검색, 관제 회원 연동, 승인 상태 관리 |
| 상태와 서버 연동 | 화면 라우팅, 회원 표시 상태 관리, 서버 세션·센터 연동 상태 확인, 업무 API 요청과 응답 표시 |

React와 JavaScript로 화면을 구성하고, React Router로 이용자·관리자 화면 이동을 연결했습니다. Redux Toolkit에서는 이용자와 관리자 상태를 별도로 관리하고 로그인 정보의 등록·해제와 새로고침 후 복원을 연결했습니다. Axios는 기존 서버 API 요청에, Kakao Maps SDK는 지도 표시와 위치 선택에 사용했습니다.

구조는 **이용자 WebView·관리자 브라우저 → 기존 업무 API**와 **웹 화면 → 지도 SDK**로 나뉩니다. 회원·접수 데이터와 최종 인증·인가는 백엔드가 담당하며, 제 기여는 그 상태를 화면과 입력 흐름에 연결하는 프론트엔드입니다. Android/iOS 네이티브 앱, 문자 전송 시스템, 지도 엔진 자체 개발은 담당 범위에 포함하지 않습니다.

### 04. 주요 구현과 기술 선택

#### 주소 검색과 지도 위치 선택을 연결한 입력 흐름

이용자가 선택한 주소를 지도에서 확인하고 실제 위치를 지정할 수 있도록 구성했습니다. 자주가는곳 등록에서는 검색 결과에서 주소 후보를 고른 뒤 지도를 이동해 장소를 지정할 수 있습니다. 접수 화면에서는 출발·도착지와 예상 경로·거리·시간을 확인하도록 연결했습니다.

서버의 정수 좌표는 값을 360000으로 나누어 지도에서 사용하는 위·경도 스케일에 맞췄습니다. 위치 선택 중에는 지도 중심 좌표를 역지오코딩해 주소에 반영하고, 좌표와 주소를 선택값으로 연결했습니다.

예상 경로는 경로 좌표가 있을 때 선으로 표시하도록 분기했습니다. 경로 데이터가 없을 때 임의의 연결선을 경로처럼 표시하지 않으며, 화면 크기나 회전 방향이 바뀌면 지도 크기와 표시 범위를 다시 적용하도록 처리했습니다.

#### 로그인과 센터 회원 연동을 구분한 화면 진입

로그인 여부와 센터 회원 연동 여부를 별도로 확인하는 구조로 화면 진입을 구성했습니다. 접수·이용내역·자주가는곳 화면에는 로그인 확인과 센터 연동 확인을 함께 적용했습니다.

보호 화면에 진입할 때 서버 세션을 확인하고, 센터 회원과 연결되지 않은 경우에는 안내 후 홈으로 이동하도록 처리했습니다. 이용자 화면의 확인 흐름과 관리자 화면의 로그인 확인도 구분했습니다.

관리자 화면에는 회원 검색·상태 필터·페이지 조회를 구성했습니다. 관리자가 웹 회원과 관제 회원을 선택해 연동을 요청하고, 보류·반려하거나 이를 취소해 대기 상태로 돌리는 동작을 기존 API에 연결했습니다. 처리 결과를 안내한 뒤 목록을 다시 조회하도록 구성했습니다.

이를 통해 이용자의 서비스 이용 상태와 관리자의 회원 처리 업무를 같은 서버 상태에 연결했습니다. 화면 진입 처리는 이용 안내를 위한 프론트엔드의 역할이며, 최종 접근 권한과 승인 판정은 서버가 담당하는 경계를 유지했습니다.

### 05. 결과와 검증

가입·주소 선택·이동 접수·이용내역 확인으로 이어지는 이용자 화면과 관리자 회원 업무 화면을 구축했습니다. 모바일 입력, 지도 위치 선택, 회원 상태에 따른 화면 진입을 기존 API에 연결한 점이 이 프로젝트의 핵심 기여입니다.

초기 개발 기간의 소스에는 지도 좌표 변환·주소 선택·조건부 경로 표시와 로그인·센터 연동 확인 구조가 포함되어 있습니다. 제공된 개발·테스트 화면에서는 주소 후보 선택, 지도 위치 지정, 경로 미리보기, 접수내역 UI를 확인할 수 있습니다.
