# 영문 프로젝트 상세 작성과 연결 계획

기준일: **2026-11-12 KST**. 상태: **실행 승인**. 실제 반영·검증 결과는 [현재 상태](../CURRENT_STATE.md#영문-상세-반영과-로컬-검증)에 기록합니다.

**기존 프로젝트 7개 항목을 유지하고, 별도의 영문 Notion 상세 페이지를 선택적으로 연결합니다.** 부산 WISEOP를 먼저 완성해 작성 기준을 잡고 파주·이케이시스, 나머지 4개 순으로 진행합니다. 한국어 원문과 기존 상세 주소는 유지하며, 영문 상세가 준비되지 않은 항목은 현재처럼 한국어 문서임을 안내합니다.

이 문서는 계획 작성 시점의 제안과 실행 순서입니다. 계획 수립 때는 문서만 작성했으며, 이후 사용자가 영문 상세 작업의 실행을 승인했습니다. 영문 Notion 작성·공개, 사이트 코드의 로컬 확인, 승인 후 커밋·배포는 각각의 반영 수준을 구분합니다.

## 현재 상세와 적용 방식

현재 카드의 상세 진입점은 하단 상세 버튼입니다. 제목·표지는 현재 코드에서 상세 링크가 아닙니다. 정규화 함수는 언어와 관계없이 원본 Notion 주소를 선택하고 `detailLanguage: 'ko'`를 반환하며, 영어 버튼은 `Case study (Korean)`으로 표시합니다.

| 방식 | 장점 | 작업과 관리 부담 |
| --- | --- | --- |
| 같은 Notion 본문에 한영 병기 | 같은 주소로 두 언어 제공 | 한국어 본문을 수정하고 문서가 길어집니다. 언어별 공유가 어렵습니다. |
| **별도 영문 Notion 상세 연결** | 한국어 원문·프로젝트 7개·현재 읽기 연결을 유지 | 영문 페이지와 대응 링크를 관리합니다. 현재 구조에 가장 적합합니다. |
| Next 내부에 영문 상세 화면 구현 | 사이트 안에서 언어와 디자인 통일 | 현재 없는 본문 블록 조회·렌더링·이미지·캐시·오류 처리가 필요합니다. 별도 범위입니다. |

영문 페이지는 기존 DB의 새 프로젝트 행으로 만들지 않습니다. 같은 개인 작업공간의 비공개 관리 위치에 일반 페이지로 준비하고, 공개 승인 후 기존 행에 연결합니다. 한국어 페이지를 영문으로 덮거나 DB를 통째로 복제하지 않습니다.

이케이시스와 SaaS에는 구현 작업의 근거가 있으므로 카드의 빈 `RoleEn`만 보고 역할 근거가 전혀 없다고 판단하지 않습니다. 다만 본문의 구현 문장을 모두 개인의 전체 개발 실적으로 바꾸지 않습니다. 원문에서 부족한 개인 분담·의사결정·성과는 편집자 확인 사항으로 분리하고, 대표 2개 작업을 먼저 진행합니다.

## 영문 원고의 구성

한국어 문장 순서를 그대로 옮기기보다 문제·본인 역할·구현·결과의 관계가 읽히도록 작성합니다. 기존 [상세 작성 기준](../NOTION.md#프로젝트-상세-작성-양식)과 [자료 전달 가이드](../PORTFOLIO_HANDOFF_GUIDE.md)를 따릅니다.

| 기본 절 | 영문 제목 | 담을 내용 |
| --- | --- | --- |
| 개요 | Overview | 대상 사용자, 결과물, 참여 기간, 팀 구성과 핵심 담당 범위 |
| 문제 | Problem and Constraints | 실제 업무 문제와 제약. 발생한 문제와 예방하려던 위험 구분 |
| 역할과 구성 | My Role and System Context | 개인·팀·기존 자산·외부 시스템의 책임 경계 |
| 구현과 선택 | Implementation and Technical Decisions | 근거가 있는 대표 사례와 선택 이유, 대안·제약 |
| 결과와 검증 | Outcomes and Verification | 확인한 구현·검증 수준, 성과와 남은 한계 |
| 자료 | References | 공개 가능한 실제 자료와 접근 조건. 이미지는 해당 사례 옆에 배치 |

부산·파주는 기존 6절을 바탕으로 작성합니다. 나머지 5개는 근거가 있는 내용을 먼저 구성하고, 빈 절을 추정으로 채우지 않습니다. 개인 역할이 불분명하면 해당 내용을 첫인칭 기여로 공개하지 않고 검토 단계에 남깁니다.

각 초안에는 공개용 영문 본문과 편집자용 대조 부분을 구분합니다. 대조 부분에는 한국어 원문 구간, 영문 표현, 이미지 순서·캡션, 확인 사항만 적고 내부 호스트·계정·관리 식별자·운영 로그는 넣지 않습니다. 이 부분은 Notion 공개 본문에 복사하지 않습니다. 원고는 해당 프로젝트를 작성할 때 하나씩 추가하며 빈 초안 7개나 새 관리 체계를 미리 만들지 않습니다.

## 이미지와 캡션

기존 허용된 이미지 42장을 기준으로 영문 캡션을 작성합니다. 실제 한국어 UI를 영어 UI처럼 재생성하지 않으며, 캡션에서 화면이 보여주는 기능·시점·환경의 확인된 범위만 설명합니다. 구성 일러스트에는 실제 화면이 아니라는 구분을 영어로도 유지합니다.

각 이미지에는 원문에서의 위치, 영문 배치 위치, 영문 캡션, 실제 화면 또는 구성 이미지의 구분을 대응시킵니다. 같은 프로젝트에서 이미 허용된 자료·예외는 유지하지만 다른 프로젝트까지 공개 허용을 확대하지 않습니다. 누락·순서 변경은 본문과 함께 검토합니다.

파일은 Notion의 정상적인 복제·첨부 재사용 또는 승인한 파일의 재업로드로 보존합니다. 만료되는 Notion 파일 URL을 새 페이지의 영구 external 이미지 주소로 고정하지 않습니다. Notion은 호스팅 파일에 임시 URL을 사용하므로, 재사용 시 파일 참조와 실제 로드를 확인합니다. [Notion 파일 객체 안내](https://developers.notion.com/reference/file-object)

## 상세 연결에 필요한 변경

다음은 계획 승인 후 적용할 계약입니다. 이번에는 속성을 만들거나 코드를 바꾸지 않습니다.

| 항목 | 제안 |
| --- | --- |
| 추가 속성 | 기존 항목의 `DetailUrlEn`, URL 종류 1개 |
| 값 입력 시점 | 본문 승인·읽기 공개·비로그인 확인이 끝난 영문 상세의 실제 주소만 입력 |
| 한국어 화면 | 기존 원본 Notion 주소 사용 |
| 영어 화면과 영문 상세 준비 | 검증한 `DetailUrlEn`을 선택하고 목적지 언어를 `en`으로 전달 |
| 영어 화면과 영문 상세 미준비 | 원본 한국어 주소와 `Case study (Korean)` 안내 유지 |
| 잘못된 값 | 잘못된 URL·인증정보 포함 URL·비HTTP(S) 주소는 한국어 링크로 복귀. 원본도 없으면 버튼 숨김 |
| 카드 번역 상태 | 기존 `translationPending`과 분리. 영문 상세가 없다고 카드까지 미번역 처리하지 않음 |
| 검색과 목록 | 기존 한영 검색·대표 순서·분야·기간·7개 항목을 유지 |

URL 형식만 유효하다고 영문 본문이나 공개 열람 가능성을 보장하지 않습니다. 페이지의 언어·대응 프로젝트·비로그인 접근을 확인한 뒤 속성을 채우는 운영 절차가 필요합니다. 서버가 방문 때마다 외부 상세를 검사하거나 비공개 초안 주소를 먼저 노출하는 방식은 사용하지 않습니다.

변경 예상 파일은 다음과 같습니다.

- [정규화 함수](../../lib/portfolio-preview.mjs): 언어에 맞는 상세 주소와 `detailLanguage` 선택. 현재 `DATA_MESSAGES.en.role`과 `highlight`에 고정된 `Korean details` 안내도 실제 목적지에 맞추거나 언어 중립 문구로 변경. 이미 작성한 `RoleEn`은 유지.
- [상세 버튼](../../components/portfolio/project-card.js)과 [문구 사전](../../lib/portfolio-messages.mjs): 실제 목적지에 맞춰 버튼·접근성 이름·`hrefLang`을 함께 선택.
- 관련 정규화 테스트·[Notion 계약 문서](../NOTION.md): 새 필드와 복귀 동작, 실제 하단 버튼 중심의 상세 진입 설명.
- 로컬 검토용 데이터: 공개할 수 있는 주소가 확정된 항목만 반영. 관리 ID·키는 계속 저장소 밖에서 관리.

기존 조회 API가 받는 속성에서 URL만 선택하므로 Notion 본문 렌더러나 사이트의 API 연결에 쓰기 권한을 추가할 필요는 없습니다. 영문 원고의 Notion 반영은 승인된 편집 도구로 진행합니다. 새 영문 페이지를 DB 행으로 추가하거나 프로젝트별 주소를 소스에 하드코딩하지 않습니다.

## 작성과 공개 순서

프로젝트별로 초안·검토·공개·연결 단계를 진행합니다.

1. **부산 로컬 초안**

   현재 한국어 본문과 이미지·캡션을 기준으로 영문 원고와 대조 부분을 작성합니다. 사용자가 내용과 표현을 검토하면 이를 공통 작성 기준으로 사용합니다.

2. **대표 프로젝트와 나머지 초안**

   파주를 같은 기준으로 작성하고 이케이시스는 개인 역할 등 확인 사항을 함께 제시합니다. 이어 나머지 4개를 진행하며 미확인 부분이 있는 프로젝트 때문에 준비된 프로젝트 전체를 멈추지 않습니다.

3. **연결 코드와 비공개 Notion 초안**

   승인된 범위에서 optional URL 필드와 연결 코드를 구현하고 로컬에서 먼저 확인합니다. 실제로 비공개임을 확인한 관리 위치에만 영문 페이지를 만듭니다. 한국어 공개 페이지 아래에 초안을 바로 만들지 않습니다. 하위 페이지는 부모 권한을 이어받으므로 부모 위치와 실제 공유 상태를 모두 확인합니다. [Notion 공유와 권한](https://www.notion.com/help/sharing-and-permissions)

4. **승인한 영문 페이지만 공개**

   검토한 영문 본문·이미지·공개 범위를 기준으로 해당 페이지에 링크 읽기 공개를 적용합니다. 전체 상위 페이지·프로젝트 DB를 공개하거나 기존 한국어 페이지의 권한을 바꾸지 않습니다. Notion Sites 발행은 이번 기본안에 포함하지 않습니다.

5. **비로그인 확인 후 연결 값 입력**

   로그인하지 않은 별도 브라우저에서 본문·표·이미지·캡션과 읽기 권한을 확인합니다. 성공한 항목에만 `DetailUrlEn`을 입력하고 로컬 카드의 실제 버튼으로 다시 엽니다. 다른 항목은 한국어 안내를 유지합니다.

6. **승인한 커밋과 배포**

   현재 로컬에 있는 영어 UI와 상세 연결 코드를 검증한 뒤, 승인된 범위로 커밋·푸시·Vercel 배포를 진행합니다. 배포 후 영어 카드가 해당 영문 상세로, 한국어 카드가 원래 상세로 열리는지 확인합니다. 이후 새 영문 상세의 URL만 갱신할 때는 데이터 재조회·ISR 반영을 확인하고 코드 변경에 필요한 배포와 구분합니다.

공개 범위에는 본문뿐 아니라 첨부 자료와 기여자 표시 등 페이지 메타데이터도 포함합니다. 새 공개 페이지의 실제 노출을 검토하며, 관리용 ID·토큰·내부 주소를 본문·첨부·Git·로그에 넣지 않습니다. [Notion의 공개 페이지 안내](https://www.notion.com/help/public-pages-and-web-publishing)

## 검증과 복구

| 검증 대상 | 완료 기준 |
| --- | --- |
| 사실과 기여 | 한국어 원문·확정 기간·역할·외부 의존성·검증 수준과 의미가 일치함 |
| 미확인 부분 | 개인 기여·성과·운영 여부를 임의로 채우지 않고 검토 항목으로 분리함 |
| 이미지 | 원문 사진과 캡션을 대응시키고 각 파일이 비로그인 상태에서 실제로 로드됨 |
| Notion 보존 | 프로젝트 7개와 기존 속성·본문·표지·한국어 상세 주소를 유지함 |
| 목적지 선택 | 한국어 링크 불변, 영어 준비 항목 선택, 미준비·잘못된 URL의 한국어 복귀, 링크 없음 처리 |
| 문구와 접근성 | 영어 연결과 한국어 복귀 각각에서 역할·기여 기본 안내, 버튼·aria-label·`hrefLang`, 새 탭 안내가 실제 목적지와 일치함 |
| 기존 화면 | 한영 전환·검색·분야·정렬·대표작 순서·기간·B 로고와 두 테마가 유지됨 |
| 실행 | 관련 테스트·빌드와 모바일·데스크톱 확인, Notion 저장값 재조회, 비로그인 실제 버튼 접근을 구분해 기록함 |
| 공개 | 영문 상세만 읽기 공개하고 부모·DB·편집·댓글·검색 노출 범위를 확대하지 않음 |

수정이 필요하면 우선 해당 `DetailUrlEn`을 비워 영어 카드가 한국어 상세로 돌아가게 합니다. 영문 페이지를 비공개로 되돌리는 작업은 필요 범위를 확인해 별도로 수행하며 한국어 원문·프로젝트 행·이미지를 삭제하지 않습니다. 공개된 영어 본문의 후속 수정도 로컬 대조 원고를 먼저 검토합니다.
