# 야구 표시·타격폼 보완 재계획

기준: **2026-11-23**. 동일 타격면 판정 보완에 이어, 사용자는 기존16개 자세를 보존한 발·기본 배치 정리와 필요한 자세의 프롬프트 기반 이미지 수정을 요청했다. 단계2의 계측/등록과 단계3의 선별 보완을 로컬에 적용했다. 원본16장은 덮어쓰지 않고 디딤·접촉 직전·마무리의 양타6장에만 통짜 하체 보폭 보완본을 사용한다. 실행 근거·한계·다음 작업은 `CURRENT_STATE.md`의 최신 발 배치 절을 기준으로 한다. 이후 승인된 유니폼 작업은 현재 상태의 공통 합성/시범 구단 절에서 별도 관리한다. 성장/수비·DB·commit/push·배포는 이 계획 범위에서 진행하지 않는다.

## 보존할 현재 기준

- 이전에 승인한 통짜 실사풍 인물·사선 타격폼을 우선한다. v4 준비/마무리와v5 중간/복귀의 양타석16PNG, 팀 합성·등번호·기존 조작을 유지한다.

## 사용자10구 관찰 이후의 우선순위 수정

관찰에서 활성 스윙 중 화면상 공/가이드 코어가 겹치지만3D 깊이가 달라 미접촉인 사례가 확인됐다. 터치의 새 조준/스윙 동시 확정, 준비 가이드가 직전 조준을 보여주는 문제도 있다. 상세 수치·범위·한계는 `CURRENT_STATE.md`의 사용자10구 분석 절을 기준으로 한다. 이 결과에 따라 **타격면·입력·결과 안내를 발 배치/인물 이미지보다 먼저 다룬다.**

1. **보이는 타격면과 판정 깊이의 관계를 먼저 정한다.** 현재3D 거리 계산이 기록과 일치한다는 사실과 화면 직관이 좋은지는 별개다. 단순히 중앙을 강조하거나 허용 반경을 조금 늘리는 것으로 깊이 때문에 겹친 사례가 해결되지는 않는다.
2. **‘같은 타격면에서의 판정’을 적용한다.** 공의3D 궤적·구속·구종은 유지하고, 공이 앞면을 통과하는 시각의 유효 스윙과 같은 면의 배트 선분/공 반경을 비교한다. 가이드도 같은 타격면의 선분을 공유한다. 기존 결과·경계·타이밍·양끝 접촉의 비교 결과를 보관하며 기존3D 연속 충돌과 동일한 정책·점수 결과로 설명하지 않는다.
3. **기존3D 판정을 보존하는 후보도 차이를 명시한다.** 깊이 표시·겹침 해설·접촉 가능한 시각의 구분으로 읽기 쉽게 할 수 있지만, 평면에서 겹치는데도 미접촉인 경우 자체가 없어지지는 않는다. 이 한계를 숨긴 채 ‘화면과 판정 완전 일치’로 보고하지 않는다.
4. **터치 조준의 의미를 함께 정리한다.** 입력 전의 이전 조준을 새 터치 목표의 미리보기로 취급하지 않는다. 원터치 유지 시 기존 미리보기/확정 조준을 구분하는 안과, 조준을 먼저 확인한 뒤 스윙하는 입력 후보를 비교한다. 드래그/떼기·2단계 입력 등은 기존 조작을 바꾸므로 별도 선택 전에 자동 적용하지 않는다.
5. **결과 숫자의 뜻을 분리한다.** miss의 ‘클릭+110ms−존 도착’과 contact의 ‘실제 접촉−존 도착’을 같은 뜻의 타이밍 숫자로 보여주지 않는다. 조준 중앙 오차와 실제 공/배트 표면 간격도 구분한다. 완료 후 코스·확정 조준·접촉/최근접 위치를 같은 시각 기준으로 복기하는 방향을 우선한다.
6. **가독성 효과와 관찰기도 정리한다.** 공 코어와 빛 번짐을 구분하고, 준비 가이드가 실제로 이미 스윙 중인 막대로 오해되지 않도록 한다. 다음 관찰은 관찰 시작 시 최신 수집 인스턴스를 새로 만들어 HMR 뒤 이전 수집 조건이 남지 않게 하고, 전체 준비 구간의 실제 보관 여부를 확인한다. 현재10구의 비행/스윙 감사와 미보관 준비 구간을 구분한다.
7. **존 통과점과 마지막 공 표시를 구분한다.** 현재 비접촉 결과 마커는 정확한 앞면 통과점을 사용하지만, 공은 그 뒤까지 계속 보이고 결과 마커는 나중에 등장한다. 이를 마지막 공의 ‘착지점’으로 오해하지 않게 통과 순간에 같은 좌표를 표시하고 결과까지 유지하는 안을 검토한다. 통과 이후의 공/궤적은 통과 마커와 시각적으로 구분한다. 현재3D 모델의 실제 타격 접촉점과 비접촉 공의 앞면 통과점은 문구/기호로 구분하며, 앞면 도착 전 타격된 공의 가상 통과점을 실제 관측점처럼 표시하지 않는다. 좌표 자체가 틀렸다는 전제로 마커를 마지막 공 위치에 옮기지 않는다.

권장 순서는 **동일 타격면 후보 비교 → 터치 조준/결과 안내 → 원본 발 배치 계측 → 필요한 통짜 자세만 수정**이다. 아래 단계1~4의 인물 보존·검증 기준은 계속 유효하며, 실제 구현에 앞서 이 우선순위와 판정 정책 선택을 함께 적용한다.

## 남은 문제와 해결의 한계

1. 통짜 PNG의 손·팔·나무배트는 고정돼 있지만 실제 판정 막대는 자유 조준의 좌우·높이·스윙 각도에 따라 움직인다. **통짜 이미지 무수정·자유 조준 유지·전 범위 완전 일치를 코드 배치만으로 동시에 달성할 수는 없다.**
2. 현재 준비 양발 중앙 정렬과 프레임별 앞발 고정은 스윙의 신발 전체가 타석 안에 있음을 보증하지 않는다.
3. contact PNG는110ms부터지만 이전760표본의 실제 접촉은약49.56~202.72ms였다. 그림의 자세명과 실제 접촉 시각은 다른 개념이다.
4. 별도 배트를 덧그리는 것은 최소 수정이 아니다. PNG의 원래 배트 제거·손 주변 복원·그립 연결·가림 처리가 필요하고 고정 손은 자유 조준 전체를 따라가지 못한다. 이번 기본안에서 제외한다.

## 단계1 — 실제 타격 범위를 쉽게 이해하도록 정리

인물과 점수 산식은 보존하고, 위 우선순위의 평면 판정 변경과 함께 가이드·결과 설명을 보완한다.

- 기존 반투명 막대의 유효 타격부 전체와 양 끝을 식별하기 쉽게 하고, 중앙은 정타에 유리한 기준점으로 구분한다. 인물 위에 두 번째 불투명 배트를 그리지 않는다.
- 안내 문구 후보: **‘막대에 공을 맞추세요. 중앙에 가까울수록 정타에 유리합니다.’** 영문도 중앙만 명중하는 조건으로 오해하지 않게 맞춘다. 중앙 외에 상하 접촉·각도도 영향을 주므로 중앙=정타 보장으로 쓰지 않는다.
- 실제 접촉이 공개된 뒤 `barrelFraction`으로 접촉 위치를 표시하는 후보를 비교한다. ‘중앙 쪽/끝 쪽’은 설명용 분류이며 기존contact/perfect/foul·점수를 바꾸지 않는다.
- 공·타구·작은 접촉 효과는 현재의 실제 `contactAtMs/contactPoint`를 유지한다. 아직 발생하지 않은 접촉점·정타 여부를 미리 표시하지 않는다.

완료 기준: 사용자에게 전체 막대가 맞는 범위이고 중앙은 유리한 위치임이 드러난다. 표시와 판정이 같은 타격면·시각의 선분을 사용하며, 기존3D 결과와의 차이를 별도로 검증한다.

## 단계2 — 기존 이미지의 배트·양발을 계측하고 배치 후보 비교

- 기존 양타석8자세에 양발 신발 외곽·접지점, 배트 손잡이/타격부 양 끝을 원본 좌표로 표시한다. 기존 애니메이션 메타데이터에 필요한 정보만 보완하고 인물 PNG는 수정하지 않는다.
- 준비·디딤·접촉·마무리·복귀와 중앙/낮음/높음/좌우 조준의 그림 배트/실제 가이드 차이, 신발/타석 포함을 비교한다. 지면에 닿은 발과 들린 발을 구분해 들린 발을 억지로 바닥에 붙이지 않는다.
- 먼저 모든 자세에 일관된 작은 평행이동·균일 배율로 개선 가능한지 비교한다. 인체 부분별 변형, 프레임마다 다른 크기, 발을 넣기 위한 급격한 위치 변경을 하지 않는다.
- 준비의 타석 중앙·현재 선수 크기·사선 폼·접지감을 함께 확인한다. 몸을 눈에 띄게 줄이거나 준비폼을 망가뜨려 발 포함 조건만 통과시키지 않는다.
- 배경에 그려진 흰 타석 선과 계산 polygon도 함께 맞는지 확인한다. 양발을 넣을 수 없다면 ‘공통 배치만으로 불가’로 남기고 단계3으로 넘긴다.

완료 기준: 전후 비교에 발 이탈·선수 크기·몸 잘림·배트/가이드 차이를 함께 제시한다. 단지canvas 안에 들어간 것을 신발 전체의 타석 포함으로 보고하지 않는다.

## 단계3 — 필요한 자세만 통짜 국소 수정 후보 제작

- 단계2에서 원본 배치로 해결되지 않는 자세만 선별한다. 예를 들어 문제 마무리1장과 접촉1장처럼 소수 후보로 시작하고 전체16장을 새로 만들지 않는다.
- 승인 PNG를 참조해 같은 얼굴·체형·질감·헬멧·그립·사선 실루엣을 보존한다. 발 위치·배트/팔의 필요한 부분만 통짜 자세 안에서 수정하고 원본은 덮어쓰지 않는다.
- 새 후보는 전체16장을 일괄 대체하지 않는다. 이번에는 사용자가 필요한 이미지 수정과 작업 진행을 허용했으므로 원본/보완 통짜 이미지·배경 배치·동작 연결을 로컬에서 대조해 선별 적용하고, 같은3031 비교 화면에서 사용자가 품질을 확인할 수 있게 남긴다. 공개/배포 승인은 별도다.
- 중앙 기준 후보를 통과해도 극단 조준까지 일치했다고 확대 해석하지 않는다. 추가 낮음/높음 자세가 필요한지, 자산 수·로딩·메모리·모바일 성능을 함께 보고 다음 범위를 정한다.
- 기존이미지+자유조준을 유지한 채 남는 차이는 명시한다. 완전 일치에 조작/물리 구조 변경이 필요하면 별도 안으로 설명하며 이번 작업에서 몰래 바꾸지 않는다.

완료 기준: 원본보다 실사풍·자세·그립·번호·연결이 나빠진 후보는 채택하지 않는다. 인체 분해/늘이기·이중 배트·손과 배트의 분리를 허용하지 않는다.

## 단계4 — 타격 동작 연결·회귀 검증

- 단계2/3의 자세를 기준으로 기존110ms 기준·520ms 스윙·900ms 시각 복귀와 원본 전환 순서를 대조한다. 추가 중간 자세는 필요한 구간에만 검토한다.

- 좌우타·4구종·양투·빠름/늦음·가장자리 조준·공유 앞면 판정·파울과 비접촉을 확인한다. 중앙/중간/양끝/끝캡/바깥의 충돌 및 점수 고정 표본을 포함한다.

- 실제 코드 변경 후 관련 테스트·lint·동일Node22/lock 환경 빌드를 수행하고, 변경 범위·해결한 점·남은 차이를 `CURRENT_STATE.md`에 기록한다.

## 권장 착수 범위

첫 구현은 **동일 타격면 판정과 원터치·가이드 구분, 통과 즉시 마커, 결과 설명 정리까지**다. 110ms 기준과20~210ms 유효 구간·64cm 전체 선분/끝캡을 유지하고, 타이밍은 모든 스윙에서 ‘입력+110ms−앞면 도착’으로 통일한다. 공·배트 표면 간격은 조준 중심 거리와 분리한다. 준비 점선은 실제 활성 스윙이 아니며 터치의 다음 목표처럼 표시하지 않는다. 통과 뒤 공은 흐리게 표시하고 앞면 사건 마커·당시 배트를 복기에 남긴다. 다음은 단계2의 원본 양발/그림 배트 계측이며, 새 인물·분절 리그를 기본 해법으로 확대하지 않는다. 커밋·배포는 별도 요청 전까지 진행하지 않는다.

위 첫 범위는 적용됐고, 현재 단계2/선별 단계3까지 진행했다. 다음 착수는 **선택한 활성16자세를 기준으로 의상 합성 영역 정리 → 피움/GG 시범 → XP 복합 배색 → 10팀 확장**이다. 원본 비교 좌표·활성 이미지 좌표를 혼용하지 않고, 원본 그림 배트와 자유 조준의 완전 일치는 별도 한계로 유지한다. 최신 실제 검수와 잔여 항목은 현재 상태 한 곳에 기록한다.
