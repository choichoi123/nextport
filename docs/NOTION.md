# Notion 콘텐츠와 연결

이 문서는 nextport의 프로젝트 데이터 출처, 콘텐츠 작성 방식, Notion 연결 계약을 관리합니다. 공통 작업 규칙은 [AGENTS](../AGENTS.md), 실행 방법은 [README](../README.md), 확인한 구현·배포 상태는 [현재 상태](CURRENT_STATE.md)를 따릅니다.

## 공개 문서와 비공개 관리 자료

이 문서와 배포 안내의 `<NOTION_DATABASE_ID>`·`<NOTION_DATA_SOURCE_ID>` 등은 실제 값이 아닌 예시 표기입니다. 그대로 환경변수에 붙여 넣지 않습니다. 현재 관리본·회사 원본·이전 개인 자료를 구분하는 실제 ID와 관리용 URL은 저장소 밖 **`%LOCALAPPDATA%/nextport/private/NOTION_CONNECTIONS.md`**에 보관합니다. 공개 문서에는 관리용 실제 ID·URL을 다시 적지 않습니다.

이 파일은 기기별 비공개 관리 자료입니다. 다른 컴퓨터에 자동으로 생기지 않으므로, 파일이 없으면 접근 가능한 Notion 관리 화면과 허용된 Vercel 설정에서 실제 값을 확인합니다. Git이나 저장소의 `.env.local`을 전달 수단으로 사용하지 않습니다. API 토큰·쿠키·비밀번호는 이 관리 자료에도 저장하지 않고 기존 Vercel Secret과 서비스의 인증 관리 화면에서 관리합니다.

아래 표의 관리 페이지 이름은 대상을 구분하기 위한 표시입니다. 실제 관리 링크는 비공개 자료에서 열고, 방문자용 프로젝트 상세 ID·링크는 기존대로 유지합니다. 공개 문서의 값 교체는 현재 Notion 연동이나 과거 Git 이력을 변경하는 작업이 아닙니다.

## 확인한 데이터 출처

현재 [공개 포트폴리오 프로젝트 목록](https://nextport-roan.vercel.app/projects)은 아래 ‘개인 워크스페이스 보존용 복제본’의 **현재 관리본**을 조회합니다. 다음 표는 전환 전 사용했던 회사 계정의 원본 출처를 보존한 것입니다. 현재 배포의 소스·연결·검증 결과는 [현재 상태](CURRENT_STATE.md#vercel-운영-db-전환)에서 관리합니다.

| 구분 | 주소 또는 ID |
| --- | --- |
| 포트폴리오 상위 페이지 | 포트폴리오 데이터베이스 (`<LEGACY_NOTION_PARENT_PAGE_ID>`) |
| 원본 프로젝트 DB | 새 데이터베이스 (`<LEGACY_NOTION_DATABASE_ID>`) |
| 원본 DB ID | `<LEGACY_NOTION_DATABASE_ID>` |
| 같은 ID의 UUID 표기 | `<LEGACY_NOTION_DATABASE_ID_UUID>` |

상위 페이지의 `<LEGACY_NOTION_PARENT_PAGE_ID>`은 프로젝트 DB ID가 아닙니다. DB 주소의 `?v=` 뒤 값도 보기 ID이므로 DB ID로 사용하지 않습니다. 콘텐츠를 편집할 때는 연결된 보기가 속한 상위 페이지와 원본 DB, 개별 프로젝트 페이지를 구분합니다.

DB ID와 API에서 사용하는 데이터 소스 ID는 구분합니다. 데이터 소스 선택 방식은 아래 연결 설정을 따릅니다. 실제로 확인한 ID는 비공개 관리 자료에, 소스 선택 방식과 운영 배포 여부는 현재 상태에 기록합니다.

### 개인 워크스페이스 보존용 복제본

아래는 현재 공개 포트폴리오가 조회하는 개인 워크스페이스의 DB입니다. 회사 계정의 원본 및 이전 개인 자료와 별도로 유지합니다. 복제 검증 범위와 옛 계정 복구 진행 상태는 [현재 상태](CURRENT_STATE.md#개인-복제본과-계정-복구)에서 관리합니다.

| 구분 | 주소 또는 ID |
| --- | --- |
| 복제본 상위 페이지 | 🟢 포트폴리오 · 현재 관리본 (`<NOTION_PARENT_PAGE_ID>`) |
| 복제본 프로젝트 DB | 프로젝트 목록 · 현재 관리본 (`<NOTION_DATABASE_ID>`) |
| 복제본 DB ID | `<NOTION_DATABASE_ID>` |
| 복제본 데이터 소스 ID | `<NOTION_DATA_SOURCE_ID>` |

API 읽기 권한과 웹 방문자의 상세 페이지 접근 권한은 구분합니다. **현재 관리본의 한국어 프로젝트 상세 8개(기존 7개와 WISEVCS)는 링크가 있는 웹의 모든 사용자에게 읽기만 허용**합니다. 상위 관리 페이지·DB와 이전 자료의 상위 페이지·DB는 비공개로 유지합니다. DB 연결 전환이나 새 항목 추가만으로 공개를 승인한 것으로 간주하지 않으며, 새 상세의 공개 범위는 별도로 정하고 각 카드의 실제 링크를 비로그인 환경에서 확인합니다. 현재 검증 결과는 [상세 공개 상태](CURRENT_STATE.md#wisevcs-운영자-웹-접수-포트폴리오)를 따릅니다.

이전에 개인 계정에서 관리하던 별도 페이지는 📦 포트폴리오 · 이전 자료 (`<PREVIOUS_NOTION_PARENT_PAGE_ID>`), 하위 DB는 프로젝트 목록 · 이전 자료 (`<PREVIOUS_NOTION_DATABASE_ID>`)입니다. 위 현재 관리본 및 전회사 계정의 운영 원본과 구분합니다. 표시 제목·페이지 아이콘과 즐겨찾기는 관리 편의를 위한 것이며, DB·데이터 소스 ID나 `Name` 등 속성 이름을 바꾸는 작업이 아닙니다.

## 운영 방식과 변경 경계

로컬 Notion 환경변수는 의도적으로 비워 둡니다. 실제 조회에 필요한 토큰과 연결 설정은 배포 플랫폼의 서버 환경변수에서 관리하는 방식을 유지합니다. 크롬은 콘텐츠 원본을 확인·편집하는 화면이고, 포트폴리오는 배포 서버에서 Notion API로 데이터를 읽습니다.

Vercel 연결·변수 수정·재배포·복구 절차는 [Vercel 전환 설명서](VERCEL_NOTION_MIGRATION.md)를 따릅니다. 배포 커밋·환경별 변수·상세 공개 접근을 함께 다루며, 이 문서의 필드 계약을 유지합니다.

사이트는 기존 내부 연결 **`nextport-preview`**를 로컬 실데이터 미리보기와 Vercel 운영 조회에 함께 사용합니다. 이름의 `preview`가 접근 권한이나 Vercel 환경을 결정하지는 않습니다. 콘텐츠 읽기만 허용하고, 개인 현재 관리본 상위 페이지 한 개와 그 하위 DB에 접근하도록 제한합니다. 운영 토큰은 Vercel의 `NOTION_TOKEN` Secret에 보관합니다. 사용자가 승인한 저장소 외부 미리보기 사본의 로컬 설정과 저장소의 빈 `.env.local`은 별도로 유지합니다. 로컬 실행 위치는 [현재 상태](CURRENT_STATE.md#개인-notion-db의-로컬-미리보기-연결)를 따릅니다.

사용자가 연결한 공식 Notion 플러그인으로 콘텐츠를 편집할 수 있습니다. 편집 전 연결 계정·작업공간과 대상 페이지의 상위 DB를 확인하고 승인된 항목만 변경합니다. 이 편집 연결은 사이트의 읽기 전용 API 연결과 별개이며, 기존 읽기 토큰의 권한을 확대하지 않습니다. 플러그인에서 지원하지 않는 편집은 로그인된 Chrome에서 보완하고, 저장 결과는 승인 초안·실제 파일·로컬 표시와 대조합니다.

현재 콘텐츠 관리는 **현재 관리본 DB**에서 수행합니다. 새 연결 생성, 토큰 재발급, DB 이전, 로컬 실데이터 연결이 항상 필요한 것은 아닙니다. 토큰을 소스·문서·공유 로그에 기록하거나 `NEXT_PUBLIC_` 환경변수와 브라우저 코드에 넣지 않습니다. 공개 프로젝트 상세 ID는 인증 토큰과 구분하며, 운영 DB·데이터 소스와 관리용 상위 페이지의 실제 ID·URL은 위 비공개 자료에서만 관리합니다.

Notion 콘텐츠 수정, 속성 이름·종류 등 스키마 변경, 페이지 삭제, 접근 권한·공개 범위 변경, 서버 환경변수 변경, 사이트 배포는 각각 영향이 다릅니다. 현재 승인된 작업에 없는 변경을 콘텐츠 정리의 일부로 확대하지 않습니다. 이미 승인된 대상과 범위 안에서는 승인을 반복해서 요청하지 않습니다.

## 프로젝트 상세 작성 양식

다른 프로젝트 담당 AI에게 자료를 요청할 때는 [프로젝트 자료 전달 가이드](PORTFOLIO_HANDOFF_GUIDE.md)의 요청문·템플릿을 사용합니다. 담당 AI가 공개 초안·내부 근거·화면 자료를 구분해 제공하고, 포트폴리오 담당 AI는 아래 양식과 승인된 범위에 맞춰 편집·반영합니다.

프로젝트 카드에는 짧은 설명을 두고, 연결되는 Notion 상세 본문은 아래 순서로 작성합니다.

1. **개요:** 프로젝트 목적, 대상 사용자, 수행 기간, 팀 구성, 결과물 링크를 적습니다.
2. **문제:** 해결하려던 구체적인 상황과 기존 제약을 설명합니다.
3. **내 역할과 기여:** 개인이 맡은 범위와 실제 구현·판단을 적습니다. 팀 전체 성과와 개인 기여를 구분합니다.
4. **주요 구현과 선택:** 핵심 기능, 기술 선택의 이유, 검토한 대안과 제약을 설명합니다.
5. **결과와 검증:** 확인한 결과·측정 방법·시점과 남은 한계를 적습니다. 구현, 테스트, 실제 운영·배포 확인을 구분합니다.
6. **자료:** 공개 가능한 저장소, 시연 영상, 문서, 비식별 화면 자료를 연결합니다.

경력·역할·기술·성과 수치를 추정해서 채우지 않습니다. 확인되지 않은 내용은 검토용 초안에서 `확인 필요`로 표시하고, 사용자 확인 전에 확정 사실로 공개하지 않습니다. 개인 기여율이나 개선 수치는 근거가 있을 때만 사용합니다.

개인정보, 비공개 고객·조직 정보, 내부 주소·계정은 공개 자료에서 제외합니다. 업무 코드와 스크린샷 원본은 공개 허용 범위를 확인하지 않고 올리지 않습니다. 화면 자료가 필요하면 공개 가능한 범위를 확인하고 필요한 비식별·재편집을 적용한 초안을 먼저 검토합니다.

### 콘텐츠 편집 절차

1. 원본 DB와 개별 프로젝트의 제목·ID를 확인하고 현재 내용을 읽습니다.
2. 수정 대상 필드·본문 구간과 변경 전후 초안을 제시합니다. 새 페이지라면 추가할 DB와 전체 초안을 제시합니다.
3. 승인된 대상과 내용만 반영합니다. 스키마·삭제·권한·공개 범위·배포 변경이 필요하면 그 영향과 필요한 범위를 별도로 명확히 합니다.
4. 저장된 원본을 다시 읽어 변경 결과를 대조합니다. 공개 사이트에서는 카드 내용, 상세 링크, 표지, 기간을 확인하고 캐시·재생성 지연 여부를 구분합니다.

원본 반영과 공개 사이트 반영은 별개의 확인입니다. 공개 배포를 확인하지 못했으면 원본 편집 완료 사실과 미확인 항목을 나누어 기록합니다.

## 프로젝트 속성 계약

속성 이름은 대소문자를 포함해 아래 계약을 유지합니다. `Name`은 정렬에 사용하는 필수 제목 속성입니다. 나머지 속성은 현재 카드에서 선택적으로 읽습니다.

| 속성 이름 | Notion 종류 | 내용 |
| --- | --- | --- |
| `Name` | 제목 (`title`) | 프로젝트 이름. 제목 속성의 이름을 `Name`으로 유지합니다. |
| `Description` | 텍스트 (`rich_text`) | 카드에 표시할 짧은 설명 |
| `NameEn` | 텍스트 (`rich_text`) | 같은 항목의 영문 카드 제목. 기존 `Name`은 유지합니다. |
| `DescriptionEn` | 텍스트 (`rich_text`) | 영문 카드 설명. 한국어 원문의 사실·기여 범위만 번역합니다. |
| `RoleEn` | 텍스트 (`rich_text`) | 근거가 확인된 개인 담당 범위의 영어 번역. 미확인 역할은 비웁니다. |
| `DetailUrlEn` | URL (`url`) | 검토·읽기 공개·비로그인 확인을 마친 별도 영문 상세 주소. 준비 전에는 비웁니다. |
| `GitHub` | URL (`url`) | 공개 가능한 저장소 주소 |
| `Youtube` | URL (`url`) | 영상 주소. `YouTube`가 아닌 `Youtube`입니다. |
| `Tags` | 다중 선택 (`multi_select`) | 사용 기술 등 태그 |
| `WorkPeriod` | 날짜 (`date`) | 시작일과 선택적인 종료일 |
| 페이지 표지 | 페이지 커버 (`cover`) | 카드 이미지. 별도 속성 열이 아닙니다. |

기존 DB에는 `URL`, `교통약자 홈페이지`, `구독 페이지`, `매니저 화면` 속성도 있습니다. 현재 카드는 이 네 속성을 읽지 않지만 콘텐츠 보존·이전 시에는 함께 유지합니다.

제목 값이 비면 대체 제목을 표시합니다. 선택 속성·설명·링크·표지가 비어 있어도 카드를 표시하며, 없는 링크는 숨깁니다. 새 메인·전체 목록은 기간을 월 단위로 표시하고, 시작일만 있으면 `종료일 미정`, 날짜가 없거나 잘못됐으면 `기간 미정`으로 표시합니다. 날짜가 비었다는 이유로 실제 진행 여부를 추정하지 않습니다. 이전 카드 소스에 남은 일수 계산은 현재 목록에서 사용하지 않습니다.

새 공통 카드는 `Description`의 명시적인 본인 담당 문장만 역할로 읽고, 근거가 없으면 상세 소개 확인 안내를 표시합니다. 일반 프로젝트 소개를 개인 핵심 기여로 자동 변환하지 않습니다. 전체 목록의 검색·분야 필터는 조회된 표시 필드에서만 동작하며 원본 Notion 속성이나 순서를 변경하지 않습니다. 기본 정렬인 ‘최근 시작 순’은 확인된 시작 월 기준이며, 시작 월이 미정인 항목은 뒤에 둡니다.

한국어는 `Name`·`Description`, 영어는 같은 항목의 `NameEn`·`DescriptionEn`·`RoleEn`을 선택합니다. 프로젝트 ID·기간·태그·표지·링크는 공유하고 별도의 영어 DB를 만들지 않습니다. 영문 원고의 초기 대조 자료는 [영문 카드 번역안](drafts/ENGLISH_PROJECT_CARDS.md)에 있으며 실제 콘텐츠의 기준은 Notion입니다.

원문에 있는 제목·설명·명시 역할의 번역이 빠졌으면 원문과 번역 준비 안내를 표시합니다. 원문에서도 개인 역할이 미확인이라 `RoleEn`을 비운 것은 번역 누락으로 표시하지 않고 영어 상세 확인 안내를 사용합니다. 영어 설명에서 개인 역할을 자동 추론하지 않습니다. 분야는 한국어 원본을 기준으로 분류한 키를 번역하고 정렬은 원래 시작 월을 사용합니다.

영문 상세는 기존 DB에 행을 추가하지 않고 현재 관리본의 비공개 상위 페이지 아래에 별도 일반 페이지로 관리합니다. 2026-11-13 WISEVCS 추가 후 한국어 DB 행과 별도 영문 상세는 각각 8개이며, 영문 카드·상세 대조 원고는 [WISEVCS 영문 원고](drafts/WISEVCS_ENGLISH_DETAIL.md)에 있습니다. 한국어 화면은 기존 원본 상세로, 영어 화면은 `DetailUrlEn`이 있으면 해당 영문 상세로 연결합니다. 공란·잘못된 URL·인증정보 포함 주소·HTTP(S) 이외의 주소는 한국어 상세로 돌아가며, 원본 주소도 없으면 상세 버튼을 숨깁니다. 버튼·접근성 이름·`hrefLang`은 실제 목적지 언어를 따릅니다. 역할·기여의 기본 안내는 특정 상세 언어를 단정하지 않습니다.

URL 형식 검사는 공개 권한·본문 언어를 보장하지 않습니다. 영문 원고와 이미지·캡션을 대조하고 해당 영문 페이지만 읽기 공개한 뒤 비로그인 실제 열람을 확인하여 `DetailUrlEn`에 입력합니다. 초안 주소를 먼저 연결하지 않으며 상위 관리 페이지·DB와 사이트의 읽기 API 권한은 유지합니다. 원고와 대조 기준은 [영문 상세 계획](drafts/ENGLISH_PROJECT_DETAILS_PLAN.md), 실제 반영·검증 수준은 [현재 상태](CURRENT_STATE.md)를 따릅니다.

현재 카드의 상세 진입점은 하단 상세 버튼이며 제목과 표지는 상세 링크가 아닙니다. API 읽기 권한과 웹 방문자의 상세 페이지 접근 권한은 다릅니다. 영문 상세 문제가 발생하면 우선 `DetailUrlEn`을 비워 한국어 상세로 복귀하고, 공개 중단이 필요한 페이지의 권한은 별도로 변경합니다.

새 메인·전체 목록의 표지는 브라우저 이미지 요소로 읽고 `contain`으로 전체 구성을 표시합니다. 로드 실패·표지 누락 시 실제 화면과 구분한 구성 스케치로 대체합니다. 기존 Next Image 카드의 호스트 목록은 `next.config.js`에 보존했지만 현재 공통 카드가 사용하는 허용 목록은 아닙니다. Notion 업로드 이미지의 URL은 만료될 수 있으므로 영구 주소로 따로 복사해 보관하지 않습니다. [Notion 파일 안내](https://developers.notion.com/reference/file-object)

## 연결 설정

### 기존 연결 확인 또는 신규 연결

기존 운영 DB의 내용을 편집하는 데 새 API 연결은 필요하지 않습니다. 다음 절차는 신규 구성을 요청받았거나 기존 연결의 권한을 점검할 때 사용합니다.

1. 대상 워크스페이스의 연결 관리 권한이 있는 계정으로 [Notion Developer portal](https://app.notion.com/developers)을 엽니다.
2. 기존 내부 연결을 확인합니다. 새 구성이 필요한 경우에만 `Internal connections`에서 연결을 생성하고 워크스페이스를 지정합니다.
3. 연결의 콘텐츠 읽기 권한인 `Read content`를 확인합니다. 사이트의 API 기능은 조회만 하므로 콘텐츠 쓰기 권한을 요구하지 않습니다.
4. 원본 프로젝트 DB의 `••• → Connections → Add connection`에서 해당 연결의 접근을 허용합니다. UI에 따라 `Add connections`로 표시될 수 있으며 Developer portal의 `Content access`에서도 대상을 설정할 수 있습니다.

연결 생성만으로 DB 접근 권한이 생기지는 않습니다. 상위 페이지에 삽입한 연결된 보기와 원본 DB의 접근 권한을 구분합니다. [내부 연결 설정](https://developers.notion.com/guides/connections-and-tokens/internal-connections), [읽기 권한](https://developers.notion.com/reference/capabilities), [연결된 데이터베이스 안내](https://developers.notion.com/guides/data-apis/working-with-databases#linked-databases)

### 서버 환경변수

| 변수 | 용도 |
| --- | --- |
| `NOTION_TOKEN` | 콘텐츠 읽기 권한과 원본 DB 접근 권한이 있는 내부 연결의 API 토큰 |
| `NOTION_DATABASE_ID` | 원본 DB ID. DB를 조회하여 데이터 소스를 자동 탐색합니다. |
| `NOTION_DATA_SOURCE_ID` | 선택 항목. 여러 소스 중 대상을 지정하거나 DB 탐색 없이 직접 조회합니다. 직접 지정하면 DB ID는 비워도 되지만 토큰은 필요합니다. |

환경변수 이름과 빈 값 예시는 [`.env.example`](../.env.example)에 있습니다. 평소 로컬 설정은 비워 두고, 실제 Notion 조회가 필요한 작업에서만 선택적으로 `.env.local`을 사용합니다. 기존 파일을 덮어쓰지 않는 준비 예시는 다음과 같습니다.

```powershell
if (-not (Test-Path -LiteralPath .env.local)) {
    Copy-Item -LiteralPath .env.example -Destination .env.local
}
```

```dotenv
NOTION_TOKEN="연결의 API 토큰"
NOTION_DATABASE_ID="원본 데이터베이스 ID"
NOTION_DATA_SOURCE_ID=""
```

`.env.local`은 Git에서 제외합니다. 실제 토큰을 `.env.example`에 저장하지 않습니다. 환경변수 변경 후 개발 서버를 다시 시작하고, 배포 환경은 해당 플랫폼에 설정한 뒤 다시 빌드합니다.

DB를 이전할 때는 원본 DB의 연결 권한과 배포 환경의 `NOTION_DATABASE_ID`를 함께 확인합니다. `NOTION_DATA_SOURCE_ID`를 지정한 상태라면 새 소스에 맞는지도 확인합니다. 실제 주소·ID는 비공개 관리 자료에 갱신하고, 현재 상태에는 대상 별칭·소스 선택 방식·연동 상태를 기록합니다. 실제 배포 결과도 별도로 확인합니다.

### 데이터베이스와 데이터 소스

현재 로컬 코드는 Notion API 버전을 `2025-09-03`으로 고정합니다. `NOTION_DATA_SOURCE_ID`가 없으면 `GET /v1/databases/{id}`의 `data_sources`를 확인하여 소스가 하나일 때 자동 선택합니다. 소스가 여러 개면 임의로 고르지 않고 명시적인 소스 ID를 요구합니다. 실제 프로젝트 조회는 `POST /v1/data_sources/{id}/query`를 사용합니다.

DB ID와 데이터 소스 ID는 서로 다릅니다. 사용할 소스 ID는 DB 설정의 `Manage data sources`에서 대상 소스의 `••• → Copy data source ID`로 확인하거나 API의 `data_sources` 응답에서 확인합니다. [공식 전환 가이드와 ID 확인 방법](https://developers.notion.com/guides/get-started/upgrade-guide-2025-09-03#step-1-add-a-discovery-step-to-fetch-and-store-the-data-source-id)

## 조회·갱신과 오류

- 세 환경변수를 모두 비우면 외부 요청 없이 빈 목록을 반환하고 `등록된 프로젝트가 없습니다.`를 표시합니다.
- 설정을 일부만 입력하거나 토큰·권한·ID가 잘못되면 원인을 설명하는 서버 오류를 발생시킵니다. 최초 빌드는 실패하며 정상적인 빈 목록으로 숨기지 않습니다.
- `Name` 오름차순으로 조회합니다. 100개를 초과하면 다음 페이지도 이어서 읽습니다.
- 외부 요청별 제한 시간은 10초입니다. 전체 페이지네이션의 합산 제한 시간을 뜻하지 않습니다.
- `/projects`는 빌드 시 생성하고 `revalidate: 1`을 사용합니다. 매초 자동 조회하지 않으며, 재검증 가능 시간이 지난 뒤 방문 요청이 오면 재생성을 진행합니다.
- 배포 후 재생성 중 API 오류가 나면 이미 생성된 페이지를 유지합니다. 즉시 최신 내용이 보이지 않는 경우 원본 저장 결과와 재생성·캐시 상태를 나누어 확인합니다.

오류는 개발 서버·빌드 터미널 또는 배포 로그의 안전한 메시지로 확인합니다. 로그를 공유할 때 토큰과 비공개 원본 응답을 포함하지 않습니다. [Notion 상태 코드 문서](https://developers.notion.com/reference/status-codes)

| 증상 | 확인할 내용 |
| --- | --- |
| 설정이 불완전하다는 오류 | 토큰과 DB ID 또는 데이터 소스 ID를 함께 설정했는지 확인합니다. |
| 데이터 소스가 여러 개라는 오류 | 대상 소스를 확인하여 `NOTION_DATA_SOURCE_ID`를 지정합니다. |
| HTTP 401 | 토큰 유효성, 복사 누락, 이전 토큰 사용 여부를 확인합니다. |
| HTTP 403 | 콘텐츠 읽기 권한과 리소스 접근 권한을 확인합니다. |
| HTTP 404 | ID 종류·값, 워크스페이스, 원본 DB의 연결 권한을 확인합니다. 공유되지 않은 리소스도 404를 반환할 수 있습니다. |
| HTTP 400 | `Name` 제목 속성의 이름·종류와 DB ID·소스 ID 혼동 여부를 확인합니다. |
| 시간 초과·네트워크 오류 | 인터넷, 프록시·방화벽의 `api.notion.com` 접근, Notion 서비스 상태를 확인합니다. |
| HTTP 429 | 잠시 후 다시 시도하고 과도한 조회 여부를 확인합니다. |
| 표지가 보이지 않음 | 허용 이미지 호스트, 업로드 URL 만료, 이미지 요청 오류를 확인합니다. |

연결 구현은 [`lib/notion.mjs`](../lib/notion.mjs), 공개 표시 필드와 실데이터·미리보기 구분은 [`lib/portfolio-preview.mjs`](../lib/portfolio-preview.mjs), 정적 생성·재검증은 [`pages/index.js`](../pages/index.js)와 [`pages/projects.js`](../pages/projects.js), 카드 표시는 [`components/portfolio/project-card.js`](../components/portfolio/project-card.js)에 있습니다. 공개 홈·목록의 무설정 빈 목록과 `/preview`의 예시는 구분합니다. 무설정 로컬 실행과 모의 API 테스트 성공을 운영 DB 인증·실제 배포 검증으로 확대하지 않습니다.
